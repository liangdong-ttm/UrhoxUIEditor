# Lua UI 转换与导出验收设计

日期：2026-09-22
状态：设计提案，待确认；本文命令、报告字段和诊断界面尚未实现。
目标：用户的 AI 能可靠转换 UI，已有导出能独立检查，预览异常能定位到具体原因。

## 1. 产品边界与完成定义

转换不是“把 Lua 表写成 JSON”，而是迁移 UI 的视觉声明，同时保留行为与运行时契约。
整体链路为：

```text
发现活动页面与构造依赖
  -> 确认设计尺寸、主题、组件和动态边界
  -> 生成候选 JSON、预览场景与迁移映射
  -> 确定性检查
  -> 编辑器预览与问题定位
  -> 按需接入游戏并验证行为
```

必须区分两种用户意图：

| 模式 | 修改内容 | 完成声明 |
|---|---|---|
| 提取供编辑 | 生成候选 JSON 和配套描述；不修改游戏入口 | “已提取，游戏仍使用原代码” |
| 接入游戏 | 在提取检查通过后，替换指定加载入口、保留行为绑定 | “已接入”，并列出运行时验证证据 |

默认提取供编辑；不能仅因用户要编辑器预览，就批量改写游戏 Lua。
用户明确要求接入时，必须检查真实调用路径；存在 JSON 文件不等于游戏使用它。
已有 JSON 可直接检查，不强制重新转换，不自动覆盖用户在编辑器中修改的文件。

完成状态按维度记录，不设置含义模糊的“准确率 98%”：

- 数据格式与依赖：通过 / 失败 / 未执行。
- 编辑器兼容性：通过 / 部分支持 / 未验证。
- 与原 UI 的语义一致性：已验证 / 部分验证 / 缺少来源。
- 游戏接入与行为：已验证 / 未验证 / 不适用。

只有数据与依赖通过，才可声称“导出数据检查通过”；
缺少原页面或引擎证据时，绝不能把它升级为“转换完全正确”。

## 3. 推荐架构：一个契约，一套检查，多处使用

不推荐只加长提示词：无法可靠识别遗漏，也无法证明导出结果。
不推荐本次开发通用 Lua 转译器：闭包、工厂、主题和运行时数据使成本失控。

推荐职责拆分：

| 模块 | 职责 | 不负责 |
|---|---|---|
| 转换 skill | 分析构造链路、识别意图、生成候选、执行检查、解释报告 | 自行发明格式；直接宣布视觉完全等价 |
| 版本化兼容契约 | 描述目标引擎格式、加载模式、字段语义与编辑器支持程度 | 为单项目增加特判 |
| 检查核心与 CLI | 确定性检查、机器诊断、已有导出审计 | 默认执行游戏 Lua；自动改文件 |
| 编辑器诊断入口 | 复用检查规则，定位源节点/资源，显示预览限制 | 另写一套冲突校验规则 |
| 受控运行时验证 | 在允许的测试工程内加载、采集、比对、验证行为 | 隐式下载/升级引擎；启动用户游戏产生真实副作用 |

首版复用本项目 JS 文档与布局模块；新增诊断核心，不把核心藏在 tests 文件里。
检查核心通过资源解析接口读取数据；CLI 提供文件系统实现，编辑器提供文件句柄实现。
同一组夹具必须在两个入口得到一致的结构/资源诊断。
文字测量证据需注明浏览器真实字体或 Node 近似测量，不混用结论。

发布时将 skill 放入正式 dev-kit 源；契约和检查工具作为固定版本随包分发，
不要求终端用户联网克隆本编辑器、不依赖开发者机器绝对路径。
编辑器与 dev-kit 使用同一版本产物和一致性夹具，而不是维护两份手工复制的规则。
引擎、skill、检查器、编辑器版本均写入报告；版本不匹配时标记能力未确认。

## 4. Skill 工作流

### 4.1 探测与分类

从用户指定页面或活动入口查找构造调用链，读取实际 UIFactory、主题和尺寸配置。
不能只 grep `UI.Panel`，也不能因为目录叫 legacy 就自动排除用户明确指定的页面。

每个发现的构造单元必须有一种归属：

- 静态页面壳。
- 可复用组件。
- 运行时创建的模板。
- 保留在 Lua 的行为或绘制逻辑。
- 有证据的非活动分支。
- 无法确定，需要补充信息。

每个“未转换”都必须给出原因和来源位置。覆盖统计是可追溯清单，
不是 AI 自报节点数：能直接发现的入口、绑定和调用要由工具交叉检查；
间接调用、动态字符串、反射式构造标记“未证明覆盖”，不能忽略。

设计尺寸从真实调用与布局规则取得；固定画布、响应式根、组件分别处理。
不能给所有根强塞 720×1280，不能把百分比布局固化为当前视口像素。

### 4.2 转换规则

- JSON 的语义以目标引擎为准；编辑器不支持的内容报告能力缺口，不改数据迎合预览。
- 读取工厂默认值、主题值、创建后 SetStyle/SetText/SetVisible 等操作，
  区分初始化视觉值和运行时更新。函数名相同不代表默认值相同。
- 保留 ID、相对层级、布局约束、资源引用和显隐语义。
- 函数、闭包、网络、存档、tween 与自绘留在 Lua，不字符串化塞入 JSON。
- 自定义控件不能无提示降级成 Panel；组件注册不完整必须报告。
- 颜色 false、0、空字符串和未声明值分别处理，不能用 truthy 默认值覆盖。
- 不因“截图不好看”补底色、改字号、取消裁切或把 fill 改 sliced；
  这属于视觉修正，必须与等价迁移分开。
- 抽组件依据共享结构及参数契约，不只依据图片被引用的次数。
- 动态列表导出容器与单项模板；预览样例不写入游戏源 JSON。
- 已有文件默认检查与对比，候选输出到临时目录；发现用户修改时不整文件覆盖。

### 4.3 生成并验收候选

先生成候选，再检查，不以“写出文件”结束。
确定性错误可以修复后重检；无法确认的默认值、单位、来源或能力差异应停止猜测。
相同诊断连续两次无进展，转交证据及具体问题，不继续随机调整。

提取模式通过后，将候选与现有文件 diff 交给用户/调用 AI 的正常变更流程。
接入模式另行修改加载入口与绑定，验证调用真实可达、失败可回退、
没有残留第二棵硬编码视觉树覆盖 JSON。

## 5. 最少必要产物

### 5.1 游戏源

`assets/ui/**/*.ui.json` 仍为引擎接受的声明，不增加检查器私有字段。
不得写入 `_layout`、`_editorId`、诊断、样例数据或来源注释。

### 5.2 一个可选的工作区描述文件

建议 `.uieditor/project.json`，用于记录无法仅从 JSON 获得的上下文：

- 文件分类：页面、组件、模板；设计尺寸模式与入口。
- 组件 type 到模板路径的映射及目标引擎版本。
- 加载方式：普通文档、参数模板、注册组件；调用方参数。
- 少量预览场景、动态挂点和模板实例参数。
- JSON Pointer 到 Lua 文件/函数/行号的映射、来源文件摘要。
- 已识别的 Find 绑定与必要节点，以及保留 Lua 的部分。

路径均为项目相对路径；不含本机用户名、token、真实存档和业务敏感数据。
这是上下文，不是第二份 UI 树；视觉字段仍只在 UI JSON 中维护。
组件清单不能单独证明运行时已注册，必须结合加载代码/运行时证据检查。
映射来源摘要改变时标记过期，不能继续信任旧行号。

已有 JSON 没有描述文件也能检查格式、资源和可计算布局；
来源完整性、参数要求和行为绑定显示“缺少上下文”，不能伪造来源。
参数化组件缺少预览尺寸时，提示提供参数，而不是直接判定组件非法。

### 5.3 检查报告

默认 stdout 输出；仅显式指定时写入 `.uieditor/reports/`。
报告不是运行时资源，也不能被底部 UI 列表误收录。

建议诊断结构：

```json
{
  "code": "UI_TEMPLATE_LOAD_MODE",
  "severity": "error",
  "domain": "runtime-contract",
  "file": "assets/ui/resource.ui.json",
  "pointer": "/width",
  "instancePath": null,
  "source": {"file": "scripts/hud.lua", "line": 42},
  "evidence": {
    "value": "$width:177",
    "loadMode": "plain"
  },
  "message": "此文件含模板参数，但已识别的调用使用普通加载。",
  "suggestedAction": "确认模板意图后传入参数表，或改为无参数的静态声明。"
}
```

上例为设计示意，不是对某个真实项目第 42 行的诊断。
报告另含 checked/skipped 项、输入摘要、工具版本和各验证维度的结论。
不能把重检前的旧报告用于证明新导出通过。

## 6. 导出后检查：五层校验

| 层级 | 核心检查 | 错误与限制 |
|---|---|---|
| 结构 | JSON、重复键、每个节点 type、children、字段类型/枚举、非法非有限数值、内部字段污染 | 不以“JSON 可解析”代替合规；扩展字段按控件契约处理 |
| 依赖 | 图片/字体/模板存在与可读、大小写、资源根、必要 meta、组件注册、模板循环 | 文件存在不等于图片可解码；UUID 需资源解析器，不能当路径判缺失 |
| 语义 | 参数类型与必需参数、Slot、加载模式、同实例 ID 冲突、绑定目标存在、源覆盖 | 不同 LoadJSON 实例可复用内部 ID；动态绑定未知就标未验证 |
| 布局 | 每个场景的有效根尺寸、有限矩形、零尺寸、完全出界、祖先裁切、文字溢出、缺省主题 | 按场景排除正常隐藏/滚动项；越界/重叠多为警告，不能全部报错 |
| 差异 | 原 UI 与 JSON 在相同字体/分辨率/数据下的结构、矩形、视觉和行为 | 缺基准时跳过并说明；不能用空白原图或默认数据制造“通过” |

错误阻断该场景或受影响页面的“通过”，独立页面继续收集诊断，
不要第一个 JSON 错误就终止全项目检查。
未知属性默认提示可能拼写错误；确认属于合法控件扩展属性后保留。
滚动区、故意隐藏弹窗、动画初始位置和装饰溢出需要上下文判断，不能机械报错。
例外记录必须限定文件/节点/场景/规则并写原因，不允许全项目屏蔽检查。

### 建议 CLI 契约（待实现）

ui-json check --project <game-root> --file assets/ui/settings.ui.json --format text

不跟随越出工程资源根的符号链接，不读取任意绝对路径。
解析、节点数、模板深度、展开数量和执行时间都有合理上限，并在超限时报告而不是崩溃。

退出码 0 仍必须查看 skipped 和验证维度，不能解释为全部能力已验证。

## 7. 预览异常的定位体验

用户打开文档即做结构/依赖检查；编辑后防抖重检，仅发布当前文档版本的结果。
错误隔离到文件，不破坏当前打开的其它文档；缺图显示占位及资源路径。
不能加载时显示原因，不只留下空画板。

编辑器提供问题列表，每条包括：

- 严重性、稳定规则码、文件、节点、具体字段和证据。
- 点击定位节点树/画布；资源问题定位 Assets。
- 参数或模板问题显示实例调用路径，区分模板源与生成实例。
- 无法可靠映射到源节点时定位文件与 JSON Pointer，不猜测节点。
- “复制诊断”提供 AI 可用文本/JSON，默认省去机器绝对路径和用户数据。

“显示不全”的诊断顺序：

1. 源文件/模板是否读到、参数是否解析、组件是否支持。
2. 资源是否存在且解码成功。
3. 节点是否在源树中、是否由场景动态生成。
4. 节点本身或祖先是否隐藏、透明、裁切。
5. 有效尺寸与世界矩形是否落在设计画布内。
6. 最后判断编辑器缩放/平移，而不是一律建议“点适应”。

内置预览场景使用可丢弃展开树：
如默认/空数据/长文本/弹窗显示，以及项目真实支持的另一种视口尺寸。
不是要求每个文档穷举所有状态；每个动态模板至少覆盖一个实例化场景。
编辑器暂不支持的效果明确标记，不能自动删除属性修复预览。

## 8. 用例与验收矩阵

| 用例 | 输入特点 | 预期输出或诊断 | 验收重点 |
|---|---|---|---|
| 设置页 | 工厂默认值、图标按钮、开关、文字 | 静态壳 + 原行为绑定 | 尺寸/图片/默认值不丢，点击仍生效 |
| 响应式 HUD | 百分比宽度、右锚、Flex | 保留约束，测试两种父级尺寸 | 不能固化当前截图坐标 |
| 工厂初始化 | 创建后 SetStyle、主题字体 | 保留初始化视觉语义，说明主题依赖 | 不能只转换构造函数参数 |
| 动态商店 | 空列表和运行时行数据 | 空容器 + 行模板 + 独立样例场景 | 无真实存档写入 JSON，空态不误报缺控件 |
| 参数资源条 | `$width:177`、缺少图标参数 | 检查调用方式和参数；补充预览上下文 | 不传 props 时不能仅因编辑器正常就通过 |
| 自定义组件 | RegisterComponent + 命名 Slot | 解析注册依赖与槽位 | 未注册报运行时问题；编辑器缺能力另报 |
| 重复模板 | 多个实例使用相同内部按钮 ID | 独立实例允许复用，同实例冲突报错 | Find 作用域不能用全项目唯一代替 |
| 隐藏弹窗 | visible=false，正常空挂点 | 正常隐藏信息；可选显示场景 | 不改源文件 visible，也不报整页缺失 |
| 资源故障 | 中文路径、大小写错、文件损坏、UUID | 分别报告解析/存在/解码/环境限制 | 不统一归结为“缺图” |
| 裁切与长文 | 两行高于容器，overflow=hidden | 带几何证据的裁切警告 | 不直接移除 overflow |
| 自绘特效 | NanoVG、tween、换帧 | 保留 Lua，明确未转换和预览边界 | 不截图成背景冒充可编辑等价转换 |
| 已导出旧项目 | 只有 JSON，没有来源映射 | 完成可执行检查，语义覆盖标未知 | 不能强制全量重导出 |
| 增量重导出 | 用户改过 JSON，Lua 也变化 | 候选 diff 与冲突提示 | 不覆盖用户调整 |
| 运行时旁路 | JSON 存在但游戏仍构造硬编码树 | 提取模式提示未接入；接入模式阻断完成 | 不能只验证 LoadJSON 字符串存在 |
| 版本不兼容 | 新控件、旧编辑器 | 保留数据，显示兼容范围 | 不静默转成 Panel |
| 分发验收 | 干净用户工程，无本机私有路径 | 能发现 skill、运行检查、得到报告 | 不依赖 `.agents` 本地忽略文件或开发者仓库 |

正例验证结果正确；反例验证稳定规则码、文件/字段定位及无源文件修改。
追加变异测试：删除图片、改错控件名、漏 children、制造 ID 冲突、
丢失 props 和改动来源摘要，确认检查器真的能发现问题。
不能只检查“工具退出成功”或报告里含有某句话。

## 9. 发布前必须项与实施顺序

### 第一阶段：契约与分发

确认引擎/编辑器版本，整理核心字段和能力差异；
把 skill 纳入正式 dev-kit 打包路径，入口按提取/接入/检查/诊断路由。
入口文档保持短，细节放在 conversion-rules、diagnostics、cases 等引用文件中。
移除项目特例和无依据强制要求，保留有证据的转换限制。

### 第二阶段：检查器与真实反例

先实现结构、资源、参数/注册、ID 和源文件保护，再实现布局提示。
提供已有 JSON 的只读检查入口及 JSON 报告。
使用两套真实项目只读数据 + 小型合成反例，不为跑通测试修改真实游戏。

### 第三阶段：编辑器接入与 AI 闭环

编辑器使用同一诊断核心；支持问题定位、复制诊断、预览场景和版本过期保护。
让独立 AI 在干净临时工程中完成“转换 → 检查 → 根据报告修复”，
再用保留答案的评估夹具判断是否遗漏页面、破坏行为或误报成功。

### 上线门槛

- 发布包实际包含 skill、检查工具与匹配契约；离开开发机器也可运行。
- 所有严重反例被检出，正常隐藏/滚动/模板实例不被误判为错误。
- 至少一个固定页面、一个动态模板页面完成代码到 JSON 再接入的受控验收。
- 提取、运行时接入和视觉等价三种状态在报告/产品文案中不混淆。
- 如果编辑器尚不支持组件/Slot 或关键主题能力，公开支持范围并限制相关完成声明，
  不宣传“任意 Lua UI 无损转换”。

暂不做：通用 Lua 编译器、执行用户 Lua 的自动沙箱平台、无来源的全自动像素修复、
跨引擎转换、假设所有用户都需要的组件库重构。
