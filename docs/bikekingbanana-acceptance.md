## 未通过完整验收的范围

### 1. 静态声明不等于运行时最终界面

- 签到重复模板的“第 1 天”“0 奖励”等为模板默认值，不是游戏存档数据。
- 签到周容器高 333，两行各 169，加 gap 8，总需求 346；声明中的
  `overflow: hidden` 会裁掉下沿。本轮保留该事实，没有改游戏 JSON 来掩盖它。
- 农场资源条 JSON 的数字 Label 没有填满父节点或父级居中规则；
  `scripts/pages/page_farm_v2.lua` 的 `resourcePill()` 另行定义了 row、居中和间距。
  这能解释部分静态预览差异，但尚未逐页确认运行时最终采用哪条构造路径。
- 后续应先确认 JSON 与 Lua 谁是权威，再做受控的设计时预览数据，不执行任意游戏 Lua，
  不把模拟数据持久化到 UI 文件。

### 2. 还没有完成运行时渲染一致性认证

- 引擎 Theme 的字号单位、字体缩放和浏览器字体度量尚未对齐；不能宣称逐像素一致。
- 控件主题默认值、旋转/缩放等变换、自绘控件、动态回调不在本轮完整验证范围。
- Yoga 版本与 UrhoX 内嵌版本的边缘行为仍需固定夹具对比。
- 后续验收应使用同一份 JSON、同一字体、同一分辨率，采集引擎截图与编辑器截图，
  对比布局矩形与文字基线，不能只看“图片出来了”。

### 3. 编辑能力仍需专项回归

- Flex 控件缩放、含百分比与双边约束的 resize、复杂改父/编组不能以此次普通拖动测试代替。
- 多选属性当前仍显示主选中节点，不等同于完整批量编辑。
- 系统文件授权写回、保存中继续编辑、保存失败恢复没有在游戏工程上做破坏性测试。
- 图片拖放、Alt 复制和跨容器改父应再用可丢弃的验收工程完成真实浏览器回归。
- 本轮针对桌面编辑器验收，不承诺手机浏览器可用。

## 后续开发约束

1. 优先补齐上述一致性与数据安全验收，不新增大规模功能入口来掩盖基础问题。
2. 每项修复必须有能触发原问题的夹具；禁止空断言、只查元素存在或只查 JSON 可解析。
3. 默认值只进入预览副本；“查看属性”和“选择节点”不得修改源文档。
4. 设计态选择不受运行态 pointerEvents 限制；隐藏、锁定、裁切和绘制顺序必须一致。
5. 底部 UI 文档只展示真实 `.ui.json`；`.meta` 仅用于资源状态，不作为可编辑 UI。
6. 不在此报告列出的未验收范围上使用“全部通过”“完全兼容”描述。
